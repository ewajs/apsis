# Architecture

> Planned. This describes the design agreed in [the decisions](decisions/README.md);
> nothing is implemented yet. Sections become "current" as steps land.

## Overview

Apsis has two halves that meet at a folder of JSON files:

```
                 ┌──────────── build time (Node, GitHub Actions) ────────────┐
catalogue.yaml ─►│ scripts/data: validate catalogue, fetch Horizons, write   │─► public/data/*.json
Horizons API  ─► │ chunks; committed archive copied as is                    │
                 └───────────────────────────────────────────────────────────┘
                 ┌──────────────────────── browser ──────────────────────────┐
data/*.json     ►│ data: load chunks ─► core: interpolate at t ─► scene / map│─► pixels
                 │                                    ui (Lit): picker, card, │
                 │                                    time slider            │
                 └───────────────────────────────────────────────────────────┘
```

There is no backend. A daily scheduled build refreshes the active missions' data and
redeploys the static site ([ADR 0008](decisions/0008-hosting-and-delivery.md)).

## Folders

```
data/
  catalogue.yaml          hand-written missions, bilingual (ADR 0009); validated by core/catalogue.ts
  orbits.json             planet orbital elements, fetched once (ADR 0010)
  archive/<body>/<year>.json   committed whole past years, never edited (ADR 0011)
scripts/data/             Node + TS: Horizons client, catalogue validation, chunk writer
src/
  core/                   pure: vector maths (math.ts), Horizons parsing, time scales,
                          Hermite interpolation, frames (ecliptic, equatorial,
                          galactic, scene) and units, orbit ellipses,
                          trails, label placement, tap picking, rotation (IAU),
                          distances, speed and light-time (the card's facts)
  data/                   browser loading: the catalogue, then years on demand
  scene/                  three.js: renderer, camera, bodies, markers, trails
  map/                    2D top-down SVG of the ecliptic plane
  ui/                     Lit components (ADR 0012): the frame, the picker and card, view and
                          language switches, tool column, time dock, info panel; shared glass styles and icons;
                          styles.css holds the design tokens
  i18n/                   @lit/localize setup, locale modules, body names
  time/                   the time controller: the clock, driving core/playback.ts
  main.ts                 wires data, the time controller, scene, map and ui
public/                   icons (from scripts/icons.ts); textures/ and CREDITS.md later
tests/                    i18n completeness; e2e/ browser tests; fixtures/ recorded Horizons responses
public/data/              generated by `npm run data` (live/, a copy of archive/, index),
                          never committed
docs/                     this file, PLAN.md, decisions/, guides/ (ui-shell, data, interpolation, map, orbits, scene, rotation, time, selection)
```

`scripts/` is never imported by `src/`. Shared types (the chunk format, the
catalogue entry) live in `src/core` and the scripts import them from there, so the
format is defined once.

## Dependency direction

```
main.ts ─► ui ─► core (types and pure helpers)
        ─► scene ─► core
        ─► map ─► core
        ─► data ─► core
core ─► nothing
```

`eslint.config.js` encodes this, external packages included (only `scene` may import
`three`; only `ui`, `map` and `i18n` Lit). `map` and `ui` may also use `i18n` for text. Files directly in `src/` belong to the app, which
nothing may import; a new folder needs its own entry there. `tsconfig.core.json`
type-checks `core` with no DOM or Node types, so browser and Node APIs fail there.

`scene`, `map`, `ui` and `data` are siblings and never import each other: `main.ts` hands
each one what it needs. ESLint's boundary rules enforce this.

## Time

One `TimeController` (`src/time/`), created in `main.ts`, owns the displayed instant
(UTC milliseconds, as the clock gives it) and its rate: paused, following now, or
playing faster, forwards or backwards (`core/playback.ts`, pure). On every change
`main.ts` converts the instant to TDB and hands it to the map and the scene, which
interpolate each body themselves. "Now" is the controller's default, not a special
case anywhere else. See [the time guide](guides/time.md).

## Rendering

The scene (loaded only when the 3D view is first shown) uses three.js `WebGPURenderer`
(WebGL 2 fallback) with a logarithmic depth buffer. Positions
stay in kilometres as 64-bit JavaScript numbers; each frame the scene subtracts the
focus's position before writing three.js positions, so the GPU's 32-bit floats only
ever see small numbers near what you're looking at
([ADR 0004](decisions/0004-frames-units-and-time.md)). Bodies are drawn at true size
with a minimum size on screen ([ADR 0005](decisions/0005-scale.md)).

## Caching and offline

The service worker precaches the app shell and textures. Data chunks are cached at
runtime: live chunks show the cached copy and refresh in the background; archived
chunks are served from the cache once fetched
([ADR 0007](decisions/0007-pwa.md)). Data is never part of the app's version, so the
daily data refresh doesn't make every visitor update the app.
